========================================
     DEMO: T-REVIEW GIT WORKFLOW
========================================

[DEMO] Simulating daily development workflow...

📝 STEP 1: Morning - Start new feature
----------------------------------------
$ cd C:\xampp\htdocs\t-review-development
$ git pull origin main
$ git checkout -b feature/fix-notification-bug

🔧 STEP 2: Development - Code and test
----------------------------------------
$ # Edit files...
$ # Test on: http://localhost/t-review-development/public
$ git add .
$ git commit -m "Fix notification URL construction - part 1"

📤 STEP 3: Evening - Push to remote
----------------------------------------
$ git add .
$ git commit -m "Complete notification bug fix

- Fixed double slash issue in URLs
- Updated CSRF token handling
- Applied fix to all notification templates"

$ git push origin feature/fix-notification-bug
$ git checkout main
$ git merge feature/fix-notification-bug
$ git push origin main

🌐 STEP 4: Deploy to Staging Server
----------------------------------------
$ ssh root@your-server-ip
$ cd /var/www/html/t-review-staging
$ git pull origin main
$ php artisan cache:clear
$ php artisan optimize

✅ Test staging: https://staging.yourdomain.com

🚀 STEP 5: Deploy to Production
----------------------------------------
$ cd /var/www/html/t-review-production
$ git pull origin main
$ php artisan cache:clear
$ php artisan config:cache
$ php artisan route:cache
$ php artisan view:cache

✅ Test production: https://yourdomain.com

🚨 BONUS: Emergency Hotfix
----------------------------------------
$ git checkout main
$ git checkout -b hotfix/critical-bug
$ # Fix bug quickly...
$ git add .
$ git commit -m "HOTFIX: Fix critical bug"
$ git push origin hotfix/critical-bug
$ git checkout main
$ git merge hotfix/critical-bug
$ git push origin main

$ # Deploy immediately to production
$ ssh root@server
$ cd /var/www/html/t-review-production
$ git pull origin main
$ php artisan cache:clear

========================================
     WORKFLOW SUMMARY
========================================

🏗️ Environment Structure:
  Local Development  → GitHub/GitLab → Server Staging → Server Production

🔄 Daily Flow:
  1. Pull latest changes
  2. Create feature branch
  3. Code and test locally
  4. Commit and push
  5. Merge to main
  6. Deploy to staging
  7. Test staging
  8. Deploy to production
  9. Verify production

🛠️ Tools needed:
  - Git (command line or GitHub Desktop)
  - SSH access to server
  - Text editor (VS Code)
  - Browser for testing

⏱️ Time per deployment: 5-10 minutes
📅 Frequency: 1-3 times per day

💡 Benefits:
  ✅ Safe deployment process
  ✅ Easy rollback capability
  ✅ Staging environment for testing
  ✅ Version control for all changes
  ✅ Team collaboration ready
